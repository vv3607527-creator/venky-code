# Earlier installer work: one-command install

> Historical development note only. Installer/update references describe earlier implementation or release targets; they do not provide current download links or prove that artifacts are available from this candidate. Verified VENKY artifacts are not available and automatic updates are disabled here.

## Installing

- **Historical installer implementation.** Earlier development code used `npx venky` to download and verify release assets, then install the relevant build. The installer is disabled in this candidate until real VENKY artifacts are verified. It targeted: macOS Apple silicon into Applications, Windows x64 with a silent install, Linux x64 as an AppImage in `~/.local/bin` with a menu entry. `npx venky --dry-run` was a historical test mode; the current candidate installer fails closed.

## macOS

- **Historical macOS local-signing work.** Earlier installer code locally signed the app with a certificate created on your machine. That description is historical; current downloads and automatic updates are unavailable in this candidate.

## Known limitations

- The first local signing changes the app's identity once, so macOS may ask one more time for keychain access to secrets VENKY Code saved before.
- Local signing does not satisfy Gatekeeper; installs through `npx` avoid the first-launch warning because the download is not quarantined.
- The Windows and Linux `npx` installs have not been tried on real machines yet.
